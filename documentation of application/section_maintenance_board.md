# Maintenance Board (Tasks Register)

## 1. Executive Summary
The Maintenance Board is the central repository for every single pending maintenance task across the entire railway network. It acts as the master backlog, pulling approved tickets from the Request Inbox and holding them until they are successfully scheduled by the AI Planner into a Block Plan.

## 2. Core Functionality & Features
This module is a high-density tabular interface designed for deep data filtering:
- **Universal Aggregation**: It combines tasks from all departments (Engineering, Signal & Telecom, Traction) into one unified view, eliminating siloed department spreadsheets.
- **Advanced Filtering**: Users can slice the data by Department, Status (`PENDING`, `SCHEDULED`, `COMPLETED`), Severity, and a dedicated "Overdue Only" toggle.
- **Deep Task Traceability**: Clicking on any task opens a Premium Drawer detailing the entire lifecycle of the task. Crucially, if a task has been scheduled, it provides a direct hyperlink to the specific `Block Plan Code` it was assigned to.
- **KPI Monitoring**: Quick-glance cards at the top track the total active backlog, critical priority tasks, and the number of tasks whose strict deadlines have expired.

## 3. User Flow & Practical Use Case
**Who uses it:** Planning Engineers and Department Heads.
**How it is used:**
1. A Department Head wants to see how much work is pending for their division. They filter by "ENGG".
2. They notice 3 tasks are marked "Overdue".
3. They open the drawer for one of the overdue tasks and click "Analyze Criticality" to generate a live risk score.
4. Armed with this score, they know they must force the AI Planner to prioritize this task in the next weekly schedule generation.

## 4. In-Depth AI Integration
The Maintenance Board utilizes predictive Machine Learning to replace human guesswork with mathematical risk assessment:
- **AI Risk Scoring (ML Classification)**: Every task possesses an "AI Risk Score" from 0 to 100. This is not a static number assigned by a human. It is generated by an underlying Machine Learning model (e.g., Random Forest Classifier).
- **Feature Importance**: When a user clicks "Analyze Criticality", the backend model analyzes multiple features: the severity level of the task type (e.g., Rail Fracture vs. Paint job), the historical failure rate of that specific track section (KM location), the time elapsed since the task was filed, and external factors like monsoon weather data.
- **Prioritization Vectoring**: The AI Planner uses this Risk Score as a heavy weight during optimization. A task with an AI Risk Score of `95/100` will aggressively force the CP-SAT solver to find a slot for it, even if it means bumping lower-priority tasks.
